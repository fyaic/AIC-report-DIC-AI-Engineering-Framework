## 2. 角色与 agent 分工

跨角色协作一律用 agent-to-agent（子代理）模拟，禁止主控 agent 一人包办所有角色：

| 角色 | 承载方式 | 主要职责 |
| --- | --- | --- |
| OD（数字智慧中心） | 主控 agent | 方法论输入、To-Be 流程、字典与权限矩阵 |
| 产品经理 | 子代理 PM-Agent | 一/二号仓库正文、版本需求确认、产品基线 |
| 研发 | 子代理 DEV-Agent | 三号仓库技术方案、代码仓 AI_CODE_INPUT 汇编与实现 |
| 测试 | 子代理 QA-Agent | 四号仓库测试用例、执行与 Bug 管理 |
| 产品总监 | 子代理 PD-Agent（评审） | 门禁评审、放行结论 |

规则：
1. 每个仓库阶段的正式正文，由对应角色的 agent 产出；其他角色只能提评审意见，不得代写。
2. 评审意见以消息（agent-to-agent）传递，收到方必须显式回应「采纳/驳回+理由」。
3. 所有跨角色往来必须留痕到对应仓库的评审/确认目录。

## 3. 硬规则（违反即停止）

1. **公共仓库只读**：`tool-repo/` 是规范真源，发现问题记录到报告「断点清单」，禁止直接修改。
2. **先判断后执行**：进入任何仓库前，先按 `warehouse-router` 逻辑完成仓库/阶段/编号判断。
3. **禁止跨仓混写**：一号仓库编号体系不得写入二号仓库正文，反之亦然。
4. **真源分层**：临时确认件、展示件不得伪装成正式真源；需求变更必须回到对应真源层。
5. **版本读取前置**：涉及版本范围/基线/变更的任务，先读零号仓库版本真源。
6. **AI 生成 + 人工确认**：每阶段产出必须留确认记录，标明「AI 生成 / 确认人 / 确认时间」。
7. **留痕登记**：AI 自动内化跳过的环节，必须在留痕中登记为「AI 自动内化跳过」。
