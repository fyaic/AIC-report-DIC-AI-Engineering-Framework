# product-baseline（运行器中立版）

执行角色：PM 产出 + PD 评审放行。输出目录：`03_二号仓库/06_产品基线/vX.Y.Z/`。

## 基线冻结（首次）

1. 前置：二号仓库方案/原型/PRD 收口；一号仓库版本需求清单确认。
2. 产出：
   - `06_产品基线/vX.Y.Z/01_产品原型/`（完整原型快照）
   - `06_产品基线/vX.Y.Z/02_产品需求/`（完整需求快照）
   - `06_产品基线/vX.Y.Z/03_需求范围/00_版本范围说明.md` + `01_版本需求清单.md`
3. PD-Agent 评审 → 放行结论写入 `00_版本范围说明.md` 头部。
4. 冻结后：零号仓库版本总表回写「已基线」；git 打 tag `baseline/vX.Y.Z`。

## 基线后变更（CHG 判定）

1. 输入必须有人工确认的 `一号仓库/02_需求确认/03_版本需求确认/vX.Y.Z/01_版本需求变更确认.md`（AI 不得代签）。
2. AI 分析产出 `03_需求范围/需求变更/CHG-NNN-*.md`：变更内容 / 影响范围 / 快照更新判断 / 分支判断。
3. 三选一结论：
   - 只留痕，不更新快照
   - 更新快照 + 版本范围说明
   - 超出修复边界 → 转新版本承接（回零号仓库建新版本卡）

## hotfix 判断口诀

修当前已冻结版本的问题 → `hotfix/vX.Y.Z`；做下一阶段新增范围 → 新版本承接。

## 禁止

1. 无人工变更确认就生成 CHG。
2. 把新版本承接伪装成当前版本 hotfix。
3. 只生成 CHG 不判断快照更新。
