# prd（运行器中立版）

执行角色：PM。输出目录：`03_二号仓库/01_方案设计 … 05_产品需求`。

## 前置

一号仓库版本需求清单已确认；零号仓库版本卡已建。

## 执行步骤（按序）

1. 读 `03_二号仓库/README.md` + `tool-repo/07_公共模板库/04_二号仓库模板/` + 一号仓库版本需求清单。
2. **方案设计**：`01_方案设计/01_全局方案/`——全局信息架构、状态机、实体清单、页面清单（对应模板目录结构）。
3. **原型**：`02_产品原型/` 页面线框描述 + `03_HTML原型/` HTML 静态原型（每页面一个 HTML）。
4. **PRD**：`05_产品需求/` 细颗粒度——一个 FR 一个 MD（`FR-NNN-*.md`），一个页面一个 PRD 索引。
5. 每份 PRD 引用上游 US 编号；状态/流程/实体/页面在本层定义，是三号仓库的直接输入。

## 细颗粒度口径（OA 试点经验）

一个 FR 对应一个 MD，一个页面对应一个 PRD；拒绝百页大文档。

## 输出契约

- FR 编号连续（FR-001…），每个 FR：描述 / 规则 / 数据项 / 异常 / 验收标准 / 来源 US。
- 页面清单 ↔ FR ↔ US 三向可追溯。

## 禁止

1. 未确认需求直接进 PRD。
2. 只改 HTML 不回写真源。
3. 基线冻结后不经 CHG 流程改正文。
