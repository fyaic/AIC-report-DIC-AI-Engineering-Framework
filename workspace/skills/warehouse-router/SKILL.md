# warehouse-router（运行器中立版）

## 输入

任务描述 + 当前仓库路径。真源根：`../tool-repo/`（只读）。

## Step 0 结构检查

1. 对照 `tool-repo/00_项目仓库模板/` 检查当前项目文档仓根层目录与 README 是否一致。
2. 不一致 → 停止，列出缺失/多余项，不开始正式落库。

## Step 1 仓库判断（按任务关键词）

| 任务关键词 | 仓库 | 后续 Skill |
| --- | --- | --- |
| 方法论/To-Be流程/组织分工/权限矩阵/字典 | 00_OD工作区 | od-demand-analyzer |
| 立项/核准证/项目环境/需求池回写/产品路标/版本卡 | 01_零号仓库 | project-governance |
| 原始资料/调研/待确认/用户故事/URD/版本需求确认 | 02_一号仓库 | req-analyze |
| 方案设计/原型/PRD/产品基线/CHG变更 | 03_二号仓库 | prd 或 product-baseline |
| 技术方案/数据模型/接口/实施编排/交付放行 | 04_三号仓库 | tech-solution |
| 测试用例/测试执行/Bug/产品验收/放行建议/运维交接 | 05_四号仓库 | qa-execute |
| 编码/AI_CODE_INPUT/前后端实现 | 独立代码仓 | 代码仓 AGENTS.md |

## Step 2 版本前置读取

凡涉及版本范围、基线、变更：先读
`01_零号仓库/04_产品路标/00_版本总表.md` 与当前 `VER-vX.Y.Z_版本卡.md`。

## 强制规则（违反即停止）

1. 先判断后执行；判断未完成禁止生成正式文档。
2. 进入目标仓库前必须读该仓库 README + 对应模板 README。
3. 禁止跨仓混写（一号编号不入二号正文，反之亦然）。
4. 真源分层：临时件/展示件不得伪装正式真源。
5. 归属不明 → 停下问产品经理，不靠猜。

## 输出契约

```text
仓库判断：<OD/零/一/二/三/四/代码仓>
阶段判断：<具体阶段>
编号体系：<该仓编号前缀>
输出目录：<绝对路径>
路由到：<Skill 名>
```
