# doc-gatekeeper（运行器中立版）

在每份正式文档写入仓库前执行。输入：待落库文件路径 + 所属仓库。

## 检查项（五项全过才放行）

1. **目录归位**：文件落在该仓库该阶段的既定目录，不是漂浮临时文件。
2. **编号合规**：文件名编号使用本仓编号体系（对照仓库 README 与模板 README）；跨仓编号 → 拦截。
3. **模板骨架**：文档结构覆盖对应模板的必备章节（模板在 `tool-repo/07_公共模板库/0X_仓库模板/`）。
4. **追溯关系**：上游输入已存在且被引用（如二号仓库文档须引用一号仓库版本需求清单；CHG 须引用变更确认）。
5. **确认留痕**：文档头部有生成信息块——
   ```text
   > 生成：AI（<模型/角色>）｜确认：<角色/人>（待确认/已确认）｜时间：<YYYY-MM-DD HH:MM>
   > 状态：草稿 / 正式 / 已废弃
   ```
   人工确认件（如 01_版本需求变更确认.md）标「AI 不得代签」。

## 输出契约

```text
门禁结论：放行 / 拦截
拦截项：<目录/编号/骨架/追溯/留痕> + 具体问题
修复建议：<一句话>
```
